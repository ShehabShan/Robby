# T-044b3b2b2b1 — durable intent journal (S98, 2026-11-01)

## Delivered scope
- `scripts/wind_step_intent_journal.py` is an HTTP-free library. It does NOT upload, check live permissions, authenticate owner consent, validate staged bytes, verify clean main, or authorize publication. Do not mistake a `Ticket` for release permission.
- `reserve(intent, GitStore(repo), spool)` consumes one independently pinned consent digest through a permanent `refs/heads/publication-intent/<consentSha256>` ref on the canonical Robby origin. Same consent with different bytes/target/review is still blocked. No reset, reclaim, deletion or automatic retry API exists.
- Input has exact fields: schema=1, kind=`WindStep isolated publication intent`, target=canonical isolated target, consentSha256, manifestSha256, placeSha256, reviewSha256, reviewedSourceSha256, mainCommit (40 lowercase hex), createdAt (positive integer Unix seconds). Pins are SHA256, not credentials or arbitrary strings. The library generates attemptNonce (256 random bits); callers cannot provide it.
- Nonce is essential: Git may report identical concurrent pushes as already up-to-date without checking their create-only leases. Distinct attempts must produce distinct root commit IDs, even with identical input and Git timestamps. D-341–D-343 record design decisions.

## Ordering and failure semantics
1. Caller creates a durable spool directory **outside ignored build/temp outputs**, e.g. `/workspace/robby-publication-journal`, with its parent directory durably created. Never use `/tmp`. The library requires an existing directory; it does not certify the caller's mount durability.
2. Exclusive consent-named local directory → fsync parent → exclusive `intent.json` write, flush/file fsync/directory fsync. Partial or failed writes intentionally leave blocking tombstones, not resumable work.
3. Require remote ref absent → Git root commit containing only canonical bounded `intent.json` → **create-only CAS** (`--force-with-lease=<ref>:`). No unconditional force push or stale tracking-ref lease.
4. Fetch exact remote ref, verify unchanged tip, schema/ref/tree modes, root ancestry and exact intent → fsync `reservation.json` → return fresh in-memory Ticket. Never reconstruct an execution ticket from disk or a remote record.
5. After the FUTURE caller's one publication attempt, `finish(ticket, outcome, store)` fsyncs an exclusive local outcome, requires the exact unchanged original intent, appends one terminal child via exact-parent CAS, verifies remote readback and fsyncs terminal receipt. It never changes the intent or updates a completed outcome.
- Before successful remote CAS, local failures prevent local reuse; another VM might still reserve an absent remote ref, but this VM cannot have sent a publication request because no Ticket was returned. Once remote CAS may have succeeded, an incomplete acknowledgment or process death must be treated as consumed/uncertain. Never infer retry safety from lack of an upload receipt.
- `inspect(consent_pin, store)` is read-only handoff: consumed=true, retryAllowed=false, publishReady=false, releaseEvidenceAccepted=false, dynamicsAccepted=false. Remote absence/read error is an exception, NEVER permission to replay. A terminal write failure leaves an already-consumed intent; no outcome is NOT proof of no publication.
- Journal remote is an intent-only root plus at most one terminal child; terminal must preserve byte-identical intent. Unknown files, modes, duplicate/noncanonical/oversized JSON, wrong ref/consent, rewritten intent, extra ancestry or changing readback fail closed.

## Outcome schema and limits
- Exact fields: schema=1, kind=`WindStep isolated publication outcome`, intentSha256 (hash of canonical nonce-bearing intent bytes), status, recordedAt, version, responseSha256, historySha256. No response bodies, review text, keys or cookies.
- Status REJECTED / UNCERTAIN has version=null and historySha256=null. HISTORY_CONFIRMED requires an exact positive integer version and independent history digest. Optional response digest is a SHA256 or null. Timestamp cannot precede intent.
- HISTORY_CONFIRMED is a durable summary supplied by a trusted caller, NOT an independently verified fact from this library. It means neither currently serving version nor downloaded-byte identity, actual Write permission, readiness, player evidence or dynamics acceptance. Caller must verify the observer result before choosing it.
- Cross-VM exclusion assumes cooperating code and a shared authoritative origin. Repository writers/admins can bypass it by deleting/rewriting refs or changing Git routing. Protect `publication-intent/*` against deletion/force-reset operationally; no GitHub protection configuration was created or verified in this task. Synthetic tests use only local bare repositories, not real reservation refs.
