## Contract for the future c0b adapter

- Create a reducer with configured capacity, prediction timeout, tombstone TTL and maximum cast lifetime. Maximum lifetime must not exceed tombstone TTL. Config production limits, essential-cue fallback, telemetry and measured network skew tolerance are c0b work; test limits are not shipping tuning.
- Keys are generation-qualified request identities unified with accepted cast IDs **by the adapter**, not raw u16 numbers. Owner and observer use the same authoritative lifetime/point. The reducer receives only validated server acceptance; it is not a remote security layer.
- Call `tick(state, now)` BEFORE reducing events, and consume every returned `clear` command. Bind the receipt to cleanup of all resources owned by that key (timers, tracks, particles, connections). Tick must keep running without incoming events. Event calls also return an action: `predict`, `adopt`, `start`, `clear`, `ignore`, `refuse`. Applying these actions exactly once is the thin engine adapter's responsibility.
- Prediction has bounded lifetime. Accepted response adopts the existing key (no double pose), stores an immutable copy of server time/accepted XYZ and replaces prediction expiry. Observer/late-after-timeout acceptance starts only the remaining phase. `phase` returns waiting/warning/active/expired and normalized phase progress; it cannot emit old contacts or damage.
- Timeline timestamps must be finite/ordered, acceptance not in the future of the supplied server-clock estimate, and lifetime bounded. A future-timestamp response is refused; adapter must explicitly buffer bounded clock-skew cases or document degraded presentation instead of adding an unbounded local wait. Tick clock is finite/nondecreasing. Existing gameplay cooldown/clock logic is untouched.
- `cancel` means authoritative rejection/terminal cancellation. It clears an existing owner once or stores a cancel-before-accept tombstone. It does **not** mean a local character slot/death change: accepted X world hazards continue until authoritative expiry; cancel just the caster-owned animation separately. Prediction timeout clears disposable local work but permits a genuinely late acceptance while the cast is still alive.
- Accepted expiry produces one clear then a tombstone. Duplicate cancel does not extend TTL. After TTL, a legitimately old acceptance is already expired because lifetime ≤ TTL; no old attack flash can restart. Identity/generation binding must prevent rewritten timestamps or new casts reusing old keys.
- Capacity NEVER silently evicts an active tell or tombstone. Newcomers return `refuse`. If unknown cancellation arrives at capacity, a single conservative `cancelledThrough` watermark suppresses later starts accepted at/before that time; no unbounded extra tombstone and no resurrection after space frees. This may hide unrelated delayed cosmetics under overload—c0b must meter/report refusals and preserve essential warnings via a separately bounded minimal-cue path. **This alone is not a solved degraded-mode renderer** (T-043i1).
- `destroy` emits cleanup for active owners, clears all storage and permanently disables that reducer. Use a new reducer after connection/generation disposal. Do not destroy the world-hazard reducer merely because the local character respawns; the adapter separates character pose resources from accepted world hazards.
